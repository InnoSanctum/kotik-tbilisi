# Помощь животным в Тбилиси / Help Pets Tbilisi

Сайт помощи уличным животным: главная страница с карточками подопечных,
отдельная страница на каждого, поиск по тегам и админка для добавления новых
записей.

Статический сайт без сборки и без фреймворков. Работает на GitHub Pages как
есть; данные берутся из Supabase, а если база не настроена или недоступна —
из локального файла `data/pets.js`.

## Особенности

- **Несколько подопечных**: карточки на главной, отдельная страница у каждого.
- **3 языка**: русский, английский, грузинский. Русский — основной: если
  перевода нет, показывается он. Выбор языка сохраняется в браузере.
- **База данных или файл**: с Supabase записи редактируются через админку;
  без Supabase сайт полностью работает от `data/pets.js`.
- **Админка**: вход по паролю, добавление / редактирование / удаление
  записей, загрузка фото, опциональный список разрешённых IP.
- **Поиск**: по тегам и по любому слову — ищет сразу по всем языкам, так что
  имя, набранное по-русски, найдётся и в грузинской версии.
- **Работает с диска**: `index.html` можно открыть двойным кликом.

assets/pet.js       сборка страницы подопечного
assets/admin.js     админка

## Быстрый старт

Ничего настраивать не нужно: откройте `index.html` — сайт работает от
`data/pets.js`. Этого достаточно, чтобы опубликовать его на GitHub Pages.

Supabase нужен только для админки: чтобы добавлять животных через браузер, а
не правкой файла.

## Как добавить подопечного

### Вариант 1: через файл (без базы)

Допишите объект в `data/pets.js`. Минимально нужны `slug`, `name`,
`mainPhoto` и `published: true`:

```js
{
  slug: 'barsik',                     // латиница, цифры и дефисы: попадёт в адрес
  published: true,
  sortOrder: 2,                       // чем меньше, тем выше в списке
  name:     { ru: 'Барсик', en: 'Barsik' },
  subtitle: { ru: 'Найден у метро' },
  shortDescription: { ru: 'Короткий текст для карточки.' },
  description:      { ru: 'Длинный текст.\n\nПустая строка — новый абзац.' },
  tags: [
    { id: 'dog', ru: 'Собака', en: 'Dog', ka: 'ძაღლი' }
  ],
  mainPhoto: {
    src: 'media/barsik-2026-08-01.webp',
    thumb: 'media/thumbs/barsik-2026-08-01.webp',
    alt: { ru: 'Барсик во дворе' }
  },
  gallery: [ /* столько фото, сколько нужно */ ],
  donate: { url: 'https://…', qr: 'assets/qr_barsik.png' },
  curator: { name: { ru: 'Имя' }, email: 'you@example.com' }
}
```

Заполнять все языки не обязательно — где перевода нет, покажется русский.

Проверьте, что ничего не сломалось:

```bash
python tools/check_site.py
```

Скрипт найдёт опечатку в `data/pets.js`, несуществующее фото, повторяющийся
`slug`, забытый русский текст и оставшийся мусор-заглушку.

### Вариант 2: через админку (с базой)

Откройте `admin.html`, войдите и нажмите «Добавить подопечного». Фото можно
загружать прямо из формы.

После изменений полезно нажать «Export seed» и положить скачанный `pets.js` в
`data/` — тогда сайт продолжит показывать актуальные карточки, даже если
Supabase недоступен.

## Как добавить фото

1. Сожмите исходник (нужен Python + Pillow: `pip install Pillow`):

   ```bash
   python tools/build_media.py "C:\путь\к\20260801_123456.jpg"
   ```

   Скрипт развернёт фото по EXIF-ориентации, уменьшит до 1600px, сделает
   превью 400×400 и **удалит все метаданные** — включая GPS-координаты и
   модель телефона. Имя файла берётся из даты съёмки.

2. Добавьте запись в `gallery` нужного подопечного (или загрузите файл через
   админку).

## Видео

Поддерживаются три типа записей в галерее и в блоке «Видео»:

```js
{ type: 'image',   src: 'media/x.webp', thumb: 'media/thumbs/x.webp', alt: {…} }
{ type: 'video',   src: 'media/x.mp4',  thumb: 'media/thumbs/x.webp', alt: {…} }
{ type: 'youtube', id:  'VIDEO_ID',     thumb: 'media/thumbs/x.webp', alt: {…} }
```

**Видео лучше не класть в репозиторий.** Git хранит все версии файлов навсегда:
один раз перезалить ролик на 50 МБ — значит навсегда добавить 100 МБ к весу
репозитория, а у GitHub Pages есть мягкий лимит около 1 ГБ на сайт.

Практичнее всего **YouTube (можно «по ссылке», не публично)**. Плеер
вставляется «фасадом»: сначала показывается только картинка-превью, а
настоящий iframe (около 1 МБ скриптов и куки) грузится **только** после клика
по кнопке play. Домен — `youtube-nocookie.com`.

Если всё же хостить видео самостоятельно: H.264 + AAC, не выше 1080p,
битрейт ~2.5 Мбит/с, обязательно `-movflags +faststart` и превью в `thumb`.

## Настройка базы данных

Нужен бесплатный проект на [supabase.com](https://supabase.com).

1. **Создайте таблицы.** Dashboard → SQL Editor → New query → вставьте
   содержимое `supabase/schema.sql` → Run.

   > Таблицы создаёт только этот скрипт. Через Table Editor руками ничего
   > создавать не нужно: получится пустая таблица `pets` с колонками `id` и
   > `created_at`, и сайт будет ругаться `column pets.slug does not exist`.
   > Если так уже вышло — удалите её и запустите скрипт заново:
   > `drop table public.pets cascade;`

2. **Создайте админа.** Authentication → Users → Add user. Пароль — длинный и
   уникальный: он единственное, что стоит между интернетом и вашими данными.

3. **Выдайте ему права.** В SQL Editor:

   ```sql
   insert into public.admins (user_id, note)
   select id, 'site admin' from auth.users where email = 'вы@example.com';
   ```

4. **Загрузите записи:**

   ```bash
   node tools/make_seed.mjs > supabase/seed.sql
   ```

   Вставьте получившийся `supabase/seed.sql` в SQL Editor и выполните.
   Команду можно повторять: существующие записи обновятся, новые добавятся.

5. **Пропишите ключи** в `config.js`:

   ```js
   supabase: {
     url: 'https://ваш-проект.supabase.co',
     anonKey: 'eyJ…'          // Project Settings -> API -> anon / public
   }
   ```

> **Про ключи.** `anon`-ключ публичный — он есть в коде любого сайта на
> Supabase, и это нормально. Данные защищает не он, а права доступа на стороне
> базы: анонимный посетитель может только читать опубликованные карточки, а
> любая запись требует входа. **Ключ `service_role` в `config.js` класть
> нельзя** — он обходит все проверки. `check_site.py` об этом предупредит.

## Доступ в админку

Два независимых рубежа:

**Пароль.** Вход через Supabase Auth. Права проверяет сама база: запись
разрешена, только если пользователь есть в таблице `admins`. Подделать запрос
из браузера не получится — правила выполняются в Postgres, а не в JavaScript.

**Список разрешённых IP (по желанию).** Пока таблица пустая, ограничения нет.
Как только появится хотя бы одна запись, сохранять сможет только тот, кто
пришёл с разрешённого адреса:

```sql
insert into public.admin_ip_allowlist (cidr, note)
values ('203.0.113.42/32', 'дом');
```

Проверьте, что сохранение всё ещё работает, **не закрывая SQL Editor**. Если
закрыли себе доступ — `delete from public.admin_ip_allowlist;` вернёт всё
назад. Список читается прямо в базе, поэтому работает и на GitHub Pages, и на
Vercel.

На Vercel можно добавить второй рубеж: переменная окружения
`ADMIN_IP_ALLOWLIST` (адреса через запятую) заставит `middleware.js` вообще не
отдавать страницу админки посторонним. На GitHub Pages этот файл не
выполняется — там работает только проверка в базе.

## Публикация

### GitHub Pages (как сейчас)

1. Загрузите файлы в репозиторий.
2. **Settings** → **Pages**.
3. Ветка `main`, папка `/ (root)`, **Save**.

Адреса страниц: `pet.html?slug=kotik`.

### Vercel

Импортируйте репозиторий — настроек не требуется, `vercel.json` уже в проекте.
Дополнительно появятся короткие адреса `/pet/kotik` и заголовки безопасности.
Обе формы адреса работают всегда, так что переезд ничего не ломает.

## Локальный просмотр

Откройте `index.html` двойным кликом — сайт работает полностью, сервер не
нужен. Поэтому записи лежат в `data/pets.js`, а не в `.json`: браузеры
запрещают читать локальные файлы через `fetch`, и с JSON-файлом страница при
открытии с диска осталась бы пустой.

## Проверка перед публикацией

```bash
python tools/check_site.py
```

Нужен Python 3 и Node.js. Ничего устанавливать не надо.

Есть и более подробные тесты (проверяют отрисовку страниц, переводы, работу
админки). Они не нужны для работы сайта и требуют одной зависимости:

```bash
cd tools/tests && npm install && npm test
```

## Управление галереей

- Стрелки на фото, клик по превью.
- Стрелки `←` / `→` на клавиатуре — когда галерея в фокусе.
- Свайп пальцем влево/вправо на телефоне.
